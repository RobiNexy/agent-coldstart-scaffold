# 核心心法 · 四条总纲

本项目采用 AI Native 工作流。你在本项目的所有决策与动作，都应从这四条心法推导。优先级由上到下递减。

---

## 心法 1：相信 ls，不要记忆

**问题**：上下文变长时，LLM 对系统提示词的注意力下降，会忘记工作流细节。

**对策**：工作流不写在提示词里，写在目录名里。目录结构是外置记忆。迷茫时运行 `ls` 或 `ls -F 任意目录/`，答案在目录名中。

**操作要求**：
- 每次会话开始：`ls -F .` 扫视地图
- 每次任务开始前：`ls` 相关子目录，确认现有资产
- 每次会话结束前：`ls 20__EDIT_BEFORE_SESSION_END/` 对照检查
- 不确定去哪找：先 `ls`，再 `rg`

---

## 心法 2：设计昂贵，代码便宜

**底层事实**：
- LLM 让"写代码"的边际成本接近 0
- 但错误的设计、模糊的决策、漂移的契约会污染后续所有产出
- 代码可以重生成，错误决策的债务难以摆脱

**价值颠倒**：
- 传统工程把代码当资产守护
- AI Native 把设计与决策当资产守护，代码是编译产物

**操作要求**：
- 改 `40__CODING_IS_CHEAP/src/` 下任何文件前，必须：
  1. 读目标文件顶部意图块
  2. 顺着 `@spec` / `@adr` / `@sequence` / `@state` 全部打开过一遍
  3. 若设计需要调整，先改设计，再改代码
  4. 严禁反过来做
- 对设计类文件（`30__DECISION_AND_DESIGN_ARE_EXPENSIVE/` 下）的改动，要比代码改动更谨慎、更慢、更需要人类裁决
- 修复 bug 时，先问"是实现错了，还是设计错了"，不要无脑打补丁
- 临时验证代码放在 `40__CODING_IS_CHEAP/src/_scratch/` 或 `_experiment-<名称>/` 这类下划线前缀目录。目录名即说明，无需额外规则。这类目录内的文件豁免意图块与设计引用要求，但禁止被生产代码引用

## 心法 3：文件名即结论

**问题**：泛化文件名（`auth.md`、`0007-database.md`）无法独立表意，每次都要打开才能定位，影响面分析也无从下手。

**对策**：文件名直接写结论。看到文件名就知道里面讲什么。

**操作要求**：
- ADR 文件名含决策：`ADR__0003-use-redis-optimistic-lock.md`
- 规格文件名含功能特征：`FEATURE__place-order-with-inventory-lock.md`
- 图文件名含场景：`SEQUENCE__payment-callback-happy-path.md`
- 可以长（50+ 字符无妨），不能含糊
- 新建文件时若想不出含结论的名字，说明对内容还不清楚，先想明白再建

**衍生能力**：影响面分析退化为一条 `rg` 命令。

## 心法 4：人类是裁决者，不是打字员

**角色划分**：
- 人类：定意图、裁决关键选择、review 简报
- AI（你）：产出规格、代码、文档、图、测试

**人类的输入口只有三个**：
1. 高层意图：对话中说"我要做 X"
2. 关键裁决：回复 `open_questions_for_human.md` 中的 Q-xxx，对 ADR 拍板
3. Review：扫 30 秒的变更简报，接受或要求调整

**操作要求**：
- 不要把人类当"写规格的"：你起草，人类审
- 不要把人类当"写代码的"：你实现，人类看结果
- 需要人类拍板的事（见 `00__AGENT_START_HERE.md` 的征求清单），停下来问
- 不要在人类明显忙时塞长文档，用简报
- 不要让人类帮你调试、补文档、改接口细节，那是你的职责
- ADR 的一切动作都由人类拍板，没有例外
