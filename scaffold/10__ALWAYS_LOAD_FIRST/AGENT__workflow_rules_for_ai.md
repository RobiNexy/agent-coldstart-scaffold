# 工作流规则

入口见 [[00__AGENT__START_HERE]]，原则见 [[AGENT__core_mindset]]。规则只约束会影响结果、安全或后续协作的动作。

## 做事

理解目标并查看相关实现、资料和已有改动；完成任务后运行与变更相关的检查。任务清楚且局部时直接执行，不必复述目标或先写计划。完成条件是目标已满足，验证结果和未解决风险已如实说明。

计划和授权是两个独立判断：

- **需要计划**：需求不清、依赖关系复杂或失败成本高时，先调查并列出简短步骤。计划本身不意味着等待批准。
- **需要授权**：会删除或不可逆地改变数据、影响生产、产生费用、向外部发送信息、暴露凭证，或造成难以撤销的结果时，执行前说明具体影响并取得明确授权。
- 用户明确要求某项动作，视为授权该动作及其通常必要的直接效果；不包括无关或超出请求范围的副作用。
- 不同解释会改变用户意图、安全性或兼容性时，先问最少必要的问题；不受影响的工作可以继续。

## 决策优先级

遵守安全、法律和平台边界；在此范围内遵循用户本轮明确指令。项目约定和已接受的 ADR 继续有效。用户明确要求改变某项决策，表示该方向由人类重新裁定，可据此调查并起草变更；若具体替代结论尚未被明确认可，ADR 保持 `Proposed`。若只是一般任务描述与旧决策看似冲突，先指出冲突再询问，不自行推断用户要废弃旧决策。

## 设计与命名

- 只有当长期有效的行为、契约、数据语义、架构决策、项目边界或质量属性/运行约束发生变化时，才新增或更新设计记录。安全、隐私、性能、可靠性和运维要求都属于质量属性或运行约束。修复实现错误且设计仍正确时，不需要改规格。
- 规格以行为与验收条件为主。契约、数据模型、ADR、图和运维手册按需采用；模板是起点，不是必填表。
- 知识库文件保留类型前缀和自解释主题或结论，标题与文件名对应。使用 `[[文件名]]` 链接，并确保链接目标在知识库中唯一。
- ADR 文件名使用 `ADR__<结论>.md`，不分配流水号。Agent 起草时标为 `Proposed`；只有人类明确接受或拒绝某个具体结论后才改为 `Accepted` 或 `Rejected`。
- 用户要求改变已接受的决策，表示可以调查并起草替代方案，不等于接受 Agent 选择的具体结论。替代 ADR 在明确获批前保持 `Proposed`；获批后才标为 `Accepted`，在新 ADR 的“取代”字段链接旧 ADR，并将旧 ADR 状态更新为 `Superseded by [[ADR__新结论]]`。若只是一般任务描述与旧决策冲突，先指出冲突并询问。
- 新 ADR 的“取代”字段是取代关系的权威来源；旧 ADR 状态中的继任链接仅作反向导航。已接受 ADR 的背景、决策、理由、后果和重新评估条件冻结；状态、提出/接受日期及取代导航等元数据可按规则更新。

## 验证与记录

- 根据变更范围运行项目已有的相关测试、类型检查、lint、构建或其他检查。修复行为缺陷时，优先增加回归测试。
- 纯文档或无行为影响的变更不运行无关门禁。失败时说明是本次引入、既有失败、环境限制还是无法判定；不删除有效测试来制造通过。
- 报告实际运行的命令与结果；未运行、失败或不确定不得称为通过。高影响动作若没有可接受的验证或回退办法，暂停执行并说明阻塞原因。
- 仅当不记录会导致下次重复调查、违反已作出的决定或漏掉阻塞工作时，才更新 `20__EDIT_BEFORE_SESSION_END/` 中对应文件。项目现状不记具体任务；任务看板只记未完成任务；待裁决文件只记尚未决定的问题。
- 问题 ID 在项目范围内必须唯一，创建后保持不变。问题解决时，持久决策写入唯一权威文档；一次性澄清不另造文档。先更新或删除任务看板中的相关阻塞引用，再从待裁决文件移除问题。
- 用户要求整理，或知识积累已妨碍查找时，再检查过期任务、失效链接和重要设计偏离。

任务有实质变更时，用简短报告说明结果和验证；只在确有待决定事项或后续任务时列出它们。简单问答和纯调查无需固定格式。
